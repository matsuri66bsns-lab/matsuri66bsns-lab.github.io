01

全体構成

Claude Code はクラウドの定期実行（ルーチン）として動き、Google Drive コネクタで Drive を読み書きします。ただしこのコネクタは新しいファイルの作成と、名前の変更・移動しかできず、既存ファイルの中身を書き換えられません。そこで、.md への追記やダッシュボードの索引の更新は Apps Script に任せ、Claude Code には「読んで考えて、結果を1ファイル書く」ことだけを担当させます。

02

.md の粒度と分類

案件（工事）ごとのフォルダに、Outlook の会話単位で1ファイルの記録を置き、案件ごとに「カルテ・決定事項・添付台帳・タスク」の4つのまとめを自動で更新します。過去6か月のメールで導入時に検証し、案件の切り方と種別を確定させます。

粒度の判断

粒度の案良い点問題判断
1メール＝1ファイル処理が単純返信の往復で文脈が切れる。ファイル数が年に数千になる不採用
1スレッド＝1ファイル質疑や是正のやりとりが時系列に並ぶ。引用の重複を除いて追記できる長期化したスレッドは長くなる（月別フォルダで分散）採用
1案件＝1ファイル1枚で全体が見える肥大化し、毎回全部を読むことになる要約（案件カルテ）として別に持つ

種別はフォルダではなく各ファイルのタグにします。1つのスレッドが「設計・監理者対応」と「工程・現場調整」をまたぐことはよくあるためです。同じ現場でも本体工事と別途工事など契約が分かれる場合は、別案件として扱います。

03

添付ファイルの読み方

Claude Code は Google Drive コネクタの read_file_content で PDF・Word・Excel・PowerPoint・画像を直接読みます。読めない形式は Apps Script がテキストにしてジョブへ書き込みます。ファイル自体は各案件の「添付」フォルダへ移し、要点を _添付台帳.md に1行ずつ記録します。

種類読み方抽出する内容
PDFClaude Code が read_file_content で読む図面・施工図: 図面名・図番・版・改訂内容
質疑回答書: 質疑番号・回答・図面反映の要否
検査記録: 指摘件数と是正期限
Excel (xlsx)・Word・PowerPoint同上見積内訳、工程表、数量表、安全書類、議事録
画像 JPG/PNG同上。15KB 未満は署名ロゴとみなして除外現場写真: 部位・状況・不具合／手書きメモ
旧形式 xls・ppt、CSV・テキストApps Script が変換してジョブに書き込む（xls は全シートを CSV 化）見積内訳、数量
ZIPApps Script が展開し、中身を同じ規則で扱う（最大15ファイル）中身の一覧と各要点
CAD・BIMDWG・JWW・DXF・SFC・RVT・IFC などは解析しないファイル名から図番・版だけ記録。同送の PDF 側を読む
転送・工事管理サービスのリンクギガファイル便・firestorage・Box・SharePoint・ANDPAD などのリンクを検出期限があれば「ダウンロードして保存」タスクを前営業日の期日で作成
HEIC・動画・その他メタ情報のみファイル名。iPhone は「互換性優先」設定を推奨
API 版との違い。コネクタは PDF を主に文字情報として読むため、図面の線や寸法の配置そのものを見て判断することはできません。図番・版・改訂欄・注記など、文字で書かれた情報が中心になります。
04

打合せ・協議の記録

音声・メモ・写真を Drive の 00_inbox/records に入れるか、ダッシュボードの「記録を追加」から投稿します。音声は Apps Script が Gemini で文字起こしし、Claude Code が議事録に整えます。

記録の種類

発注者打合せ／設計定例／行政協議・検査／工程会議・職長会／現場確認・検査／近隣説明／社内会議／電話メモ

ファイル名の先頭に [P-2026-001][行政協議・検査] を付けると案件と種類が確実に決まります。ダッシュボードからの投稿では自動で付きます。

入れられるもの

  • 音声（m4a / mp3 / wav）: 45MB まで
  • テキスト・Markdown: 走り書きのメモで構いません
  • PDF・Word・写真: 手書きメモやホワイトボード

議事録の型

  • 基本情報の表（日時・場所・相手先・出席者・目的）
  • 協議事項の表: 論点／相手の指摘・要望／回答・協議結果／根拠（法令・仕様書・図面と温度感）／状態（解決・要対応・継続協議・参考）
  • 決定事項 → 案件の _決定事項.md にも追記
  • 本人のタスクと、相手側の宿題（相手待ち）。近隣説明で約束したことはタスクになります
  • 次回の日時・議題、聞き取れなかった点
録音は相手の了承を取ってから。官公庁の窓口では断られることがあります。その場合は、協議直後に要点を口頭で吹き込んだ音声や、手書きメモの写真でも十分に構造化できます。
05

タスクの読み取りと分解

メール1通・記録1件ごとに、あなたが行動すべきことを1つの成果（提出・回答・承認取得・手配・是正）単位で読み取り、段取りに分解して提案します。採用したものだけがタスクになります。

拾う・拾わない

  • 拾う: To に自分が入り、依頼・質問・提出を求められている／本文で名指し／自分の送信メールで約束したこと
  • 拾わない: CC だけの共有、他者宛ての依頼、お礼・受領連絡のみ
  • 自分が依頼して返事を待っているもの（質疑回答・施工図・見積・承認）→ 相手待ち
  • 送信メールで報告書などを送ったら、該当タスクを完了候補として提示

期日の決め方

  • 期限の明記あり → 最終工程を期限の1営業日前に置き、サブタスクは逆算
  • 検査・打設・搬入に関わる段取り → その日の前営業日までに完了
  • 許認可・届出（道路使用許可など）→ 審査日数を見込んで前倒し
  • 「至急」→ 当日か翌営業日／「今週中」→ 今週最終営業日
  • 記載なし → 回答は2営業日、書類作成は5営業日を既定とし「既定」と明示
  • 土日・祝日は Google の祝日カレンダーで判定

分解の例（監理者の配筋検査指摘）

#サブタスク期日
1指摘3件の是正内容を鉄筋業者の職長へ指示する9/28
2開口補強筋の径を監理者に質疑で確認する9/28
3是正状況を確認し、写真を撮影する9/30
4是正報告書を作成して所長の確認を受け、監理者へ提出する10/1

期日の根拠: 是正報告の期限 10/2(金) の明記 → 1営業日前に提出。10/6(火) の打設前に完了が必要なため優先度「高」。あわせて「監理者から補強筋径の回答」が相手待ちに入ります。

提案→ 採用 →未着手→進行中→完了／相手待ち／却下

導入手順

手順はすべて導入ガイドにまとめました。コードや式は「コピー」ボタンで貼るだけです。全体で約40分です。

  1. Apps Script を作ってウェブアプリとして公開するscript.new にコード（1ファイル）・Dashboard.html・appsscript.json の3つを貼り、「自分のみ」でデプロイします。
  2. Gemini の API キーを発行するGoogle AI Studio で発行します。
  3. ダッシュボードで初期設定をする初回はダッシュボードに設定画面が出ます。氏名・業務用アドレス・Gemini キーを入れると、Drive のフォルダと定期処理が自動で作られます。スクリプトプロパティを手で入力する必要はありません。
  4. 解析ルーチンに Google Drive を接続して有効にするルーチン「秘書AI 解析ルーチン」は作成済みです（毎日 6:49〜17:49 の毎時、Claude Sonnet 5）。コネクタの紐づけは claude.ai の画面でしかできないため、そこだけ操作が必要です。
  5. Power Automate でフロー A（受信）と B（送信）を作るアクション名を英字（html2text・attachments_select・mail_json）に変えることで、日本語画面でも式がそのまま使えるようにしています。メルマガの除外は Claude が行うので、フローには入れていません。
  6. テストメールで確認し、後日に過去6か月の初期分析初期分析は、フロー C で書き出したあと、ダッシュボードの「稼働状況」のボタンで始めます。
08

実行間隔と利用量

Claude API の従量課金はなくなり、Claude Code の実行はあなたの Claude のプランの利用枠から消費されます。Power Automate は標準コネクタのみ、Apps Script と Drive は無料枠内、Gemini の文字起こしは少額（Google AI Studio の料金表を確認）です。

実行間隔の案1日の実行回数反映までの時間向いている使い方
1時間おき（7〜18時）・採用12回最大 約1時間20分（夜間分は翌朝）当日中の対応が多い現場向け
2時間おき（6〜20時）8回最大 約2時間20分朝・昼・夕に確認する使い方。利用枠を抑えたいとき
1日3回（6時・12時・17時）3回最大 半日利用枠を節約したい。日次の整理が中心
1回の実行で扱うのは最大15件です。1日40通のメールなら1時間おきで十分に収まります。ジョブがない回はすぐ終わるので、利用枠の消費はわずかです。利用枠に達したときは解析待ちが溜まるだけで、次の枠で順に処理されます（データは失われません）。
09

注意点

メール経由の指示の混入

ルーチンは Drive への書き込み権限を持つため、メール本文に紛れた指示に従わないよう手順書で固く禁じています（共有・削除・URL を開く・リポジトリへの書き込みを禁止）。心配な場合は、ルーチンを動かす環境のネットワークを必要最小限に絞ってください。

公開リポジトリ

このリポジトリは GitHub Pages で公開されています。置いてあるのはコードと手順書だけで、メールや議事録は Drive にしか保存しません。ルーチンにはコミット・プッシュを禁止しています。

ルーチンの停止に気づく

ルーチンが止まると解析待ちが増え続けます。ダッシュボードのホームと「稼働状況」に解析待ちの件数と最終解析の時刻が出るので、半日以上動いていなければ確認してください。

公開範囲
