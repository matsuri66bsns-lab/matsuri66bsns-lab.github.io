02

.md の粒度と分類

過去メールの分析は Outlook に接続できるようになってから行います（この作業環境からはメールボックスを読めないため）。そこで、行政協議と施主打合せを扱う建築実務を前提にした初期案を用意し、導入時に過去メールで検証して確定させる二段階にしました。

推奨: 「案件 ＞ スレッド」の2階層と、案件ごとに更新されるまとめ文書

粒度の案良い点問題判断
1メール＝1ファイル処理が単純返信の往復で文脈が切れる。ファイル数が年に数千になる不採用
1スレッド＝1ファイルOutlook の会話単位で往復が時系列に並ぶ。引用の重複を除いて追記できる長期化したスレッドは長くなる（月別フォルダで分散）採用
1案件＝1ファイル1枚で全体が見える肥大化し、Claude が毎回全部を読む必要がある。追記の衝突要約文書（カルテ）として別に持つ

種別（行政協議・施主対応など）はフォルダではなく、各ファイルのフロントマターに付けるタグにします。1つのスレッドが「行政協議」と「設計調整」をまたぐことはよくあり、フォルダで分けると迷子になるためです。

添付ファイルの解釈

ファイルの種類ごとに読み方を変えます。ファイル自体は各案件の「添付」フォルダへ移し、内容の要点は _添付台帳.md に1行ずつ記録します。図面は図番と版で追えるようにしておくと、「最新は Rev. いくつか」をすぐ答えられます。

04

行政協議・施主打合せの記録

記録は Drive の 00_inbox/records に入れるか、ダッシュボードの「記録を追加」から投稿します。メールと同じ案件フォルダに入るので、協議とメールの経緯を1本のタイムラインで追えます。

入れられるもの

  • 音声（m4a / mp3 / wav）: Gemini API で文字起こし → Claude で構造化（Gemini のキー未設定なら、文字起こし済みテキストを同じ名前で入れる）
  • テキスト・Word・PDF: 走り書きのメモや Teams の文字起こしをそのまま
  • 写真: 手書きメモやホワイトボード

ファイル名の先頭に [P-2026-001][行政協議] を付けると案件と種別が確実に決まります。ダッシュボードからの投稿では自動で付きます。

議事録の型

  • 基本情報の表（日時・場所・相手先・出席者・目的）
  • 協議事項の表: 論点／相手の指摘・要望／回答・協議結果／根拠（条文・要綱・温度感）／状態（解決・要対応・継続協議・参考）
  • 決定事項 → 案件の _決定事項.md にも追記
  • 本人のタスク（分解・期日付き）と、相手側の宿題（相手待ち）
  • 次回の日時・議題、聞き取れなかった点
録音するときは相手の了承を取ってください。行政窓口では録音を断られることもあります。その場合は手書きメモの写真や、協議直後に口頭で吹き込んだ要点メモでも十分に構造化できます。
05

タスクの読み取りと分解

Claude がメール1通ごとに「本人がやるべきこと」を判定し、1つの成果（提出・回答・決定・手配）ごとにタスクを作ります。提案は自動では確定せず、あなたが採用したものだけがタスク一覧に入ります。

拾う・拾わない

  • 拾う: To に自分が入り、依頼・質問・確認を求められている／本文で名指し／自分の送信メールで約束したこと
  • 拾わない: CC だけの共有、他者宛ての依頼、お礼・受領連絡のみ
  • 自分が依頼して返事を待っているもの → 相手待ちとして別管理（催促の判断に使う）
  • 送信メールで回答を送ったら、該当タスクを完了候補として提示

期日の決め方

  • 期限の明記あり → 期限の1営業日前に最終工程を置き、サブタスクは逆算
  • 「至急」→ 当日か翌営業日／「今週中」→ 今週最終営業日／「〇日の打合せまでに」→ 前営業日
  • 記載なし → 回答は2営業日、資料作成は5営業日を既定とし「既定」と明示
  • 土日・祝日は Google の祝日カレンダーで判定し、休日は前倒し

分解の例（確認申請の指摘事項）

#サブタスク期日
1指摘事項を整理し、対応方針（修正/説明）を決める9/28
2日影図を GL+4m 測定面で再作成するよう CAD 担当に依頼9/28
3排煙計算書と避難経路図を修正する9/30
4回答書を作成し所長チェックを受ける10/1
5電子申請システムで回答書と修正図を提出する10/2

期日の根拠: 本文に回答期限 10/5(月) の明記 → 期限の1営業日前に提出。各サブタスクには想定時間も付きます。

提案→ 採用 →未着手→進行中→完了／相手待ち／却下

タスクは - [ ] 回答書を作成 📅 2026-10-02 ⏫ 🆔 t-… の書式で .md に書き出すので、Drive を Obsidian で開けば Tasks プラグインでもそのまま扱えます。

07

導入手順

所要時間の目安は2〜3時間です。コードはこのリポジトリの secretary/gas/ にあります。

A. Google 側（Apps Script）

  1. Apps Script プロジェクトを作るscript.new で新規作成し、secretary/gas/ の各ファイルを同じ名前で作って貼り付けます。appsscript.json は「プロジェクトの設定 → 『appsscript.json』マニフェスト ファイルをエディタで表示する」をオンにしてから置き換えます。clasp を使う場合は clasp create --type standalone --rootDir secretary/gas → clasp push。
  2. API キーを用意するAnthropic Console で API キーを発行し、月の利用上限を設定します。音声の自動文字起こしを使う場合は Google AI Studio で Gemini の API キーも発行します。
  3. スクリプト プロパティを登録するANTHROPIC_API_KEY、OWNER_NAME（氏名）、OWNER_EMAILS（自分のアドレス。エイリアスもカンマ区切りで）、OWNER_ROLE（例: 設計事務所の意匠設計担当・PM）、任意で GEMINI_API_KEY。
  4. setup() を実行する初回は権限の承認画面が出ます。マイドライブに「秘書AI」フォルダが作られ、10分おきの処理と毎朝7時の処理が登録されます。
  5. Web アプリとしてデプロイする「デプロイ → 新しいデプロイ → ウェブアプリ」。実行ユーザーは「自分」、アクセスは「自分のみ」。発行された URL をブックマークし、iPhone ではホーム画面に追加します。

B. Microsoft 側（Power Automate）

先に Outlook の仕分けルールで、明らかなメールマガジンを別フォルダへ移しておくと、フローが起動する回数そのものが減ります。

フロー A: 受信メール → Drive

  1. トリガー: Office 365 Outlook「新しいメールが届いたとき (V3)」フォルダー: 受信トレイ／添付ファイルを含める: はい。
  2. 変数を初期化: key（文字列）@{formatDateTime(convertFromUtc(triggerOutputs()?['body/receivedDateTime'],'Tokyo Standard Time'),'yyyyMMdd-HHmmss')}_@{substring(replace(guid(),'-',''),0,8)}
  3. HTML からテキストへ（コンテンツ変換）コンテンツ: triggerOutputs()?['body/body']。アクション名は「HTML_からテキストへ」のままにします。
  4. 作成: 除外アドレス／除外ドメインJSON 配列で登録します。例 ["news@example.jp"]、["seminar-portal.example.jp"]。ダッシュボードの「稼働状況」に出る送信元を順次追加します。
  5. 条件: 配信メールか式で次を入れ、「はい」側は何もしない（終了）にします。
    @or(contains(outputs('除外アドレス'), toLower(triggerOutputs()?['body/from'])), contains(outputs('除外ドメイン'), last(split(toLower(triggerOutputs()?['body/from']), '@'))), contains(body('HTML_からテキストへ'), '配信停止'), contains(body('HTML_からテキストへ'), '配信解除'), contains(toLower(body('HTML_からテキストへ')), 'unsubscribe'))
  6. 「いいえ」側: 添付を保存（Apply to each）対象 triggerOutputs()?['body/attachments']。条件 items('Apply_to_each')?['isInline'] が false のとき、Google Drive「ファイルの作成」: フォルダー /秘書AI/00_inbox/attachments、名前 @{variables('key')}__@{items('Apply_to_each')?['name']}、内容 @{base64ToBinary(items('Apply_to_each')?['contentBytes'])}
  7. 選択: 添付一覧From triggerOutputs()?['body/attachments']、マップ: name / contentType / size / isInline をそれぞれ item()?['name'] などで。アクション名は「選択」。
  8. 作成: メール JSON（下のコードをそのまま貼る）続けて Google Drive「ファイルの作成」: フォルダー /秘書AI/00_inbox/mail、名前 @{variables('key')}.json、内容 @{outputs('作成')}。添付の保存より後に置いてください。
{
  "schema": "mail.v1",
  "direction": "in",
  "id": "@{triggerOutputs()?['body/id']}",
  "internetMessageId": "@{triggerOutputs()?['body/internetMessageId']}",
  "conversationId": "@{triggerOutputs()?['body/conversationId']}",
  "receivedAt": "@{triggerOutputs()?['body/receivedDateTime']}",
  "from": "@{triggerOutputs()?['body/from']}",
  "to": "@{triggerOutputs()?['body/toRecipients']}",
  "cc": "@{triggerOutputs()?['body/ccRecipients']}",
  "subject": "@{triggerOutputs()?['body/subject']}",
  "importance": "@{triggerOutputs()?['body/importance']}",
  "bodyText": "@{body('HTML_からテキストへ')}",
  "bodyPreview": "@{triggerOutputs()?['body/bodyPreview']}",
  "attachments": "@body('選択')",
  "webLink": "https://outlook.office.com/mail/deeplink/read/@{encodeUriComponent(triggerOutputs()?['body/id'])}"
}
「作成」の入力が正しい JSON として認識されていれば、本文に引用符や改行が含まれていても自動でエスケープされます。貼り付け後に入力欄が赤くならないことを確認してください。webLink のリンクで Outlook が開かない環境では空文字にして構いません。

フロー B: 送信メール → Drive

フロー A を「名前を付けて保存」で複製し、トリガーのフォルダーを「送信済みアイテム」に、JSON の direction を "out" に変え、除外の条件を削除します。送信メールから「自分が約束したこと」「相手に頼んだこと（相手待ち）」「回答済み（完了候補）」を読み取ります。

フロー C: 過去メールの書き出し（初期分析用・1回だけ）

  1. 手動トリガー入力: 開始日（例 2026-03-25）、日数（例 180）。変数 i（整数）＝0。
  2. Do until: i が日数以上上限を「回数 400・タイムアウト PT6H」に広げます。中で変数 day ＝ @{formatDateTime(addDays(triggerBody()?['date'], variables('i')), 'yyyy-MM-dd')}。
  3. メールの取得 (V3) を受信トレイと送信済みの2回上位: 25、検索クエリ: received:@{variables('day')}、添付を含める: いいえ。1日25通を超える日は一部だけになりますが、分類の提案には十分です。
  4. 選択 → Drive に保存マップ: receivedAt, direction（"in"/"out"）, from, to（toRecipients）, subject, preview（bodyPreview）, conversationId。受信と送信を union() でまとめ、/秘書AI/00_inbox/bootstrap/@{variables('day')}.json に保存。最後に i を1増やします。
  5. Apps Script で bootstrapTaxonomy() を実行時間切れになると1分後に自動で続きから再開します。結果は _system/分類提案.md と、ダッシュボードの「提案 → 新しい案件の候補」に出ます。

導入前の確認と注意点

社内規程

業務メールを Google Drive と Claude API に送る構成です。個人の Google アカウントへの保存や外部 AI の利用が規程で制限されていないか、情報システム部門に確認してください。会社契約の Google Workspace があればそちらを推奨します。

Power Automate の DLP

テナントのデータ損失防止ポリシーで Outlook（ビジネス）と Google Drive（非ビジネス）の併用が禁止されているとフローが保存できません。その場合は管理者に相談が必要です。

API データの扱い

Anthropic の商用規約では、API で送った内容は既定でモデルの学習に使われません（最新の規約を確認してください）。Console で月の利用上限を必ず設定します。

公開範囲

ダッシュボードは「自分のみ」でデプロイします。「秘書AI」フォルダは共有しないでください。db.json と .md には取引先の個人情報が含まれます。

なりすまし・指示の混入

外部からのメール本文に AI への指示が紛れていても、この仕組みは記録とタスク提案しか行わず、メール送信や削除はしません。タスクも採用するまで確定しないため、影響は限定されます。

Apps Script の上限

個人アカウントはトリガーの合計実行時間が1日90分（Workspace は6時間）です。1日40通程度なら収まります。大きな PDF で応答が遅いときは EFFORT_MAIL を low にします。

この設計はまだ実環境では動かしていません。導入時は、フロー A で自分宛にテストメールを数通送り、00_inbox/mail に JSON ができること、10分以内に案件フォルダへ .md が書かれることを確認してから本運用にしてください。
