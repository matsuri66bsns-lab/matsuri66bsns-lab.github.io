秘書AI の仕組み

メール1通が、タスクになるまで

Power Automate は Outlook から Google Drive への運搬、Apps Script は Drive 上のファイル操作と記録の更新、Claude Code は判断を担当します。3者は直接つながらず、Google Drive のフォルダを介して受け渡します。

Power Automate Apps Script（GAS） Claude Code Google Drive（受け渡し場所） あなた

メール1通の所要時間

8:00 に届いたメールの例です。いちばん長いのは Claude Code の実行を待つ時間で、最大でおよそ1時間20分かかります。18時以降に届いたメールは翌朝 6:49 の回で解析します。

それぞれが行う処理

処理名の横の英字は、コード上の関数名やアクション名です。

Power Automate

Outlook から Drive への運搬係。中身は判断しません。

フロー A：受信トレイにメールが届くたび
  1. メールを受け取る新しいメールが届いたとき (V3)
    本文・宛先・添付ファイルを含めて取得
  2. 保存名を決めるkey
    受信日時（日本時間）＋乱数8桁。例 20260925-081200_ab12cd34
  3. 本文をテキストにするhtml2text
    HTML メールを文字だけに変換
  4. 添付を1つずつ保存Apply to each ＋ 条件
    本文に埋め込まれた画像を除き、00_inbox/attachments/<key>__元の名前 として原本のまま保存
  5. 添付の一覧を作るattachments_select
    名前・種類・サイズ
  6. メール JSON を組み立てるmail_json
    差出人・宛先・CC・件名・本文・会話 ID・Outlook へのリンク・添付一覧
  7. JSON を保存ファイルの作成
    00_inbox/mail/<key>.json。添付の保存が終わってから作るので、Apps Script が取りこぼさない
フロー B：送信済みアイテムに入るたび
  1. フロー A と同じ処理
    違いは "direction": "out" だけ。自分が約束したこと・相手に頼んだことの材料になります
フロー C：導入時に1回（手動）
  1. 過去6か月を日ごとに書き出す
    件名・差出人・宛先・冒頭文だけを 00_inbox/bootstrap/日付.json に保存（本文全体は読まない）
やらないこと：メルマガの判定、案件の振り分け、要約。判断はすべて Claude Code に任せ、フローは単純な運搬だけにしています。

Apps Script（GAS）

Drive 上のファイル操作と記録の更新係。判断はしません。

10分おき：tick
  1. 解析結果を反映するapplyResults_
    results の結果 JSON を読み、種類ごとに次を行います。
    • メール：メルマガ判定なら保管庫へ。案件を確定（新しい工事は「提案」として案件マスタに追加）。添付を案件の「添付」フォルダへ移して _添付台帳.md に1行追記。スレッドの .md に追記（初回は作成）。_決定事項.md に追記。db.json に要約・提案タスク・相手待ち・予定・完了候補を登録
    • 記録：議事録 .md を作成し、音声・文字起こしを「記録/原本」へ移動
    • 日次：_案件カルテ.md を書き直し、「今日の段取り」を保存
    • 壊れた結果：最大3回まで解析をやり直させる
  2. メールから解析ジョブを作るprepareMailJobs_
    作成から2分以上たった JSON を読み、同じ key の添付を集めます（届くまで最大15分待つ）。ZIP は展開し、PDF・Word・Excel・画像は Claude が読めるよう形式を直して fileId を記載。旧形式の xls などはテキストに変換、CAD は「読めない」と明記。返信の引用部分を削り、案件一覧・営業日カレンダー・同じスレッドの進行中タスクを添えて Google ドキュメントとして jobs に作成。原本は _queued へ
  3. 記録から解析ジョブを作るprepareRecordJobs_
    音声は Gemini で文字起こししてから、メモ・PDF・写真はそのまま材料にしてジョブを作成
  4. 止まったジョブを戻すrecoverStaleJobs_
    「処理中」のまま24時間たったジョブを「待機」に戻す
  5. タスクと案件の集計を更新writeTasksMd_ ／ syncProjectsToDb_
    動きのあった案件の _タスク.md を書き出し、未完了・期限切れ・相手待ちの件数を更新
毎朝 5:30：prepareDailyJob
  1. 日次ジョブを作る
    直近2日に動いた案件の材料（前回のカルテ・メール要約・記録・決定事項・未完了タスク）と、今日の期限・予定・相手待ちをまとめる。6:49 の解析で「今日の段取り」と案件カルテになります
ダッシュボードを操作したとき：Web アプリ
  1. 画面を表示apiGetDb
    db.json を読んで返す。.md は登録済みのものだけ読める
  2. タスクの採用・完了・編集apiUpdateTask
    db.json を更新し、案件の _タスク.md を書き直す
  3. 記録の投稿apiSubmitMemo ／ apiUploadRecord
    メモはその場で解析ジョブに、ファイルは 00_inbox/records に保存
  4. 案件の追加・編集apiUpsertProject
    _system/案件マスタ.md を更新
  5. 初期設定・初期分析apiSaveSettings ／ apiStartBootstrap
    フォルダと定期処理の作成、過去メールの初期分析ジョブの作成
やらないこと：分類・要約・タスクの判断。Apps Script は Claude Code が書いた結果を、決まった書式で .md と db.json に書き込むだけです。

Claude Code（解析ルーチン）

判断の担当。毎時49分（6:49〜17:49）に Claude Sonnet 5 で動きます。

  1. 待機中のジョブを探す
    名前が「秘書AI_JOB_待機_」のもの。最大15件、日次 → 記録 → メールの順
  2. 名前を「処理中」に変えてから読む
    ジョブ本体と、ジョブに fileId が書かれた添付だけを Drive コネクタで読む
  3. 手順書に沿って判断する
    メルマガか、どの案件か、要約・決定事項・懸案、本人のタスクとサブタスク・期日・根拠、相手待ち、予定、添付の図番・版
  4. 形式を検証してから結果を書く
    validate.mjs で確認し、results に新しいファイルとして作成。ジョブの名前を「処理済」に変える
やらないこと：.md や db.json の編集、ファイルの共有・削除、メール内の URL を開くこと、リポジトリへの書き込み。メール本文に指示が書かれていても従いません。
